# Section 5.9 비교 시험 기록

상태: **시스템 시험 완료, 원본 기반 재작성 비교는 자료 대기**. 현재 작업에서 원본 필기 PDF와 강의안은 제공되지 않았다. 저장소의 완성 원고와 JPEG는 확인했지만 이를 원본 두 종류 대신 사용하지 않았다. 자동 생성 원고나 품질 점수를 꾸며내지 않았다.

기존 원고: `content/notes/gm-ch05-59.md`, 기준 commit `1ccf3174d8953267b0df768be87a9765c40a5e18`.

문자 수는 frontmatter·공백·제목·fenced code·인라인/블록 수식·이미지/데모 줄을 제외한다. 강조 기호·표·캡션은 남는다. 이는 구조 비교용 수치이며 원본 누락률이나 읽기 난이도 점수가 아니다. 다음 명령으로 현재 저장소의 기준값과 비교 화면을 다시 만든다.

```sh
npm run notes -- compare 5.9 --baseline content/notes/gm-ch05-59.md
npm run notes -- preview 5.9
npm run notes -- serve 5.9
```

실제 Chrome에서 기준 원고를 기존 renderer로 검사했다. desktop 1470px와 mobile 390px에서 MathJax 오류가 0개였고, display 블록 36개가 유지되었다. mobile 문서 폭과 scrollWidth는 모두 390px였다. 비교 화면은 기존 원고와 “생성 후보 없음”을 나누어 표시한다. WaveNet iframe이 화면에 들어올 때 로딩되며, Standard는 RF span/연결 입력 5/5, 두 Layer에 dilation 2·2를 설정하면 5/3과 gap 2, Reset은 16/16과 gap 0을 표시했다. mobile 그래프는 폭 346px의 컨테이너 안에서 744px 너비를 가로 스크롤한다. 원본 PDF에 대한 수학적 완전성 검토와 생성 후보의 문체 평가는 수행하지 않았다.

기존 59개 테스트와 새 워크플로 테스트가 함께 다음을 확인한다: 원본 필기·강의안 누락 차단, 페이지 지정 검사, 원본 변경 감지, 재준비 시 보존, 불명확한 수식·미대응 항목 차단, QA 지문 변경 감지, Chapter 예산, 기존 경로·main·비교 패킷의 통합 차단, 원본/개인 작업의 공개 번들 제외, 새 노트와 공개 영수증 생성, 비교 원고 보존, 실제 renderer를 복사한 preview의 격리.

## 자료가 제공되면 수행할 품질 비교

5.9의 두 PDF와 실제 PDF 페이지 맵을 등록하고 `baseline`을 지정한 뒤 `prepare 5.9`를 실행한다. 원고 작성 전 기존 원고와 독립적으로 두 원본의 항목 목록을 만들고, 후보를 작성한 후 다음 평가표를 채운다. 각 행의 결과는 pass / revise / blocked이며 구체적인 sourceId·PDF 페이지·항목·본문 구절을 함께 적는다.

| 평가 축 | 확인 방법 | 현재 결과 |
|---|---|---|
| 수학 내용 보존 | 원본의 모든 식·조건·예제를 기존/후보 양쪽에 대응 | blocked: 두 PDF 없음 |
| 해석 정확성 | 부호·첨자·정의역·시점 이동·수용영역 범위와 연결 수 구분 | blocked: 원본 대조 필요 |
| 첫 독자의 이해 | 기호 정의, 필요한 중간 계산, 문단 연결을 항목별 비교 | blocked: 후보 없음 |
| 설명의 절제 | 출처 없는 확장, 중복 설명, 불필요한 예제 점검 | blocked: 후보 없음 |
| 그림의 정확성 | 실제 원본/논문과 축·연결·정규화·캡션 비교 | blocked: 후보 없음 |
| 인터랙티브 | 독립 수학 검증과 실제 조작, Chapter 전체 예산 | 기존 커널/조작 회귀만 확인 |
| 렌더링 | desktop/mobile, 수식·표·이미지·링크·그래프 | 기존 원고/비교 화면만 확인 |

후보가 완성되어도 자동으로 기존 5.9를 교체하지 않는다. 비교 결과를 PR에서 검토한 뒤 작성자가 교체 범위를 따로 지시한다.
